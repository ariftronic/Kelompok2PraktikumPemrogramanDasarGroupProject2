1. ATURAN UMUM
---------------------------------------------------------------------
- Semua file data berada di folder data/ dan memakai encoding UTF-8.
- Satu baris mewakili satu data. Tidak ada baris judul.
- Kolom dipisahkan tanda "|" (pipa).
- Kolom tanpa nilai ditulis "-", sehingga jumlah kolom selalu tetap.
- Tanggal ditulis YYYY-MM-DD, misalnya 2026-11-05.
- Nilai data tidak boleh mengandung "|" atau baris baru. Input seperti
  itu ditolak program sebelum disimpan.

---------------------------------------------------------------------
2. FILE, URUTAN KOLOM, DAN CONTOH ISI
---------------------------------------------------------------------
a. mahasiswa.txt
   Kolom : nim|nama|no_hp|status_aktif
   Nilai : status_aktif = aktif | tidak aktif
           (diatur program: aktif selama ada transaksi aktif)
   Contoh:
     M001|Andi Pratama|081234567890|aktif
     M002|Budi Santoso|081298765432|tidak aktif
     M005|Eko Prasetyo|-|tidak aktif

b. alat.txt
   Kolom : kode|nama|kategori|kondisi|status
   Nilai : kondisi = baik | rusak ringan | rusak berat
           status  = tersedia | dipinjam | tidak tersedia
           kategori bebas; kategori baru langsung bisa dipakai
   Contoh:
     A001|Multimeter Digital|pengukuran|baik|dipinjam
     A003|Power Supply DC|sumber daya|baik|tersedia
     A004|Breadboard|prototyping|rusak ringan|tidak tersedia

c. transaksi.txt
   Kolom : id|nim|tgl_pinjam|batas_kembali|status
   Nilai : status = dipinjam | sebagian dikembalikan | selesai
           batas_kembali tidak boleh sebelum tgl_pinjam; saat transaksi
           dibuat, batas_kembali = tgl_pinjam + 7 hari
   Contoh:
     T001|M001|2026-11-02|2026-11-09|dipinjam
     T003|M003|2026-11-03|2026-11-10|sebagian dikembalikan

d. detail_transaksi.txt
   Satu baris untuk setiap alat di dalam sebuah transaksi.
   Kolom : id|kode|status|kondisi|tgl_kembali
   Nilai : status = dipinjam | dikembalikan
           selama alat masih dipinjam, kondisi dan tgl_kembali = -
   Contoh:
     T003|A004|dikembalikan|rusak ringan|2026-11-05
     T003|A005|dipinjam|-|-

e. pemeliharaan.txt (Tantangan C)
   Kolom : id|kode|tgl_masuk|tgl_selesai|status
   Nilai : status = dalam perbaikan | selesai
           selama alat masih diperbaiki, tgl_selesai = -
   Contoh:
     P001|A006|2026-10-20|2026-10-24|selesai
     P002|A009|2026-11-06|-|dalam perbaikan

f. log.txt (Tantangan D)
   Teks bebas, satu aktivitas per baris, diawali waktu [YYYY-MM-DD HH:MM].
   Contoh:
     [2026-11-10 10:15] Mahasiswa M001 ditambahkan
     [2026-11-10 10:20] Transaksi T001 dibuat oleh M001 (A001, A002)

g. data/karantina/<nama file data>
   Berisi baris yang dilewati saat program memuat data, ditulis apa
   adanya dengan format file asalnya, misalnya karantina/transaksi.txt:
     T777|M001|2026-11-01
     T003|M003|2026-13-45|2026-11-10|sebagian dikembalikan

h. laporan/<jenis>_<tanggal>.txt (Tantangan F)
   Laporan teks yang rapi untuk dibaca, bukan untuk dimuat program:
     alat_dipinjam_2026-11-25.txt
     alat_rusak_2026-11-25.txt
     riwayat_M003_2026-11-25.txt

---------------------------------------------------------------------
3. KAPAN DATA DIBACA DAN DITULIS
---------------------------------------------------------------------
Dibaca:
- Sekali saat program mulai, berurutan alat, mahasiswa, transaksi,
  lalu pemeliharaan. Isinya dimuat ke dictionary dengan kunci kode alat,
  NIM, ID transaksi, dan ID pemeliharaan. Detail transaksi disimpan di
  list daftar_detail milik transaksinya.

Ditulis ulang (mode w, lewat file sementara .tmp lalu os.replace):
- Setiap tambah, edit, hapus, transaksi baru, pengembalian, dan
  perubahan pemeliharaan.
- Bila satu operasi mengubah beberapa file (misalnya transaksi baru
  mengubah transaksi.txt, detail_transaksi.txt, alat.txt, dan
  mahasiswa.txt), semua file sementara ditulis dulu dan baru
  menggantikan file lama setelah semuanya berhasil.
- Sekali lagi saat program ditutup lewat menu 0.
- Operasi yang ditolak aturan bisnis tidak menulis apa pun.

Ditambah di akhir file (mode a):
- log.txt untuk setiap aktivitas.
- data/karantina/<file> untuk setiap baris yang dilewati.

---------------------------------------------------------------------
4. FILE YANG HILANG, KOSONG, ATAU BERISI BARIS SALAH
---------------------------------------------------------------------
- File atau folder yang belum ada dibuat otomatis tanpa error.
- File kosong dianggap tanpa data.
- Baris yang jumlah kolomnya salah, berisi nilai tidak valid, berkunci
  ganda, atau merujuk data yang tidak ada dilewati dengan peringatan
  [PERINGATAN], lalu dipindahkan ke data/karantina/. Setelah itu file
  utama langsung ditulis ulang agar sama dengan data di program.
- Alat yang tercatat dipinjam tetapi transaksinya tidak ditemukan
  ditandai "tidak tersedia" sampai diperiksa petugas.

---------------------------------------------------------------------
5. ALASAN MEMILIH FORMAT DAN PEMISAH
---------------------------------------------------------------------
- Pemisah "|" mudah diurai dengan split() dan join() (json, csv, dan
  pickle tidak boleh dipakai) dan hampir tidak pernah muncul di nama
  atau kategori.
- "-" untuk nilai kosong menjaga jumlah kolom tetap, sehingga baris
  yang rusak mudah dikenali.
- detail_transaksi.txt dipisah dari transaksi.txt agar jumlah alat per
  transaksi tidak dibatasi dan pengembalian tercatat per alat.
- Tanggal YYYY-MM-DD bisa dibandingkan dan diurutkan sebagai teks.
